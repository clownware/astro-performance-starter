You just cloned a template that ships with 95+ Lighthouse scores, a semantic design token system, and working AI development workflows. Here's how to make it yours.

<Callout type="note" title="Prerequisites">
You'll need Node.js 24.x and pnpm. If you don't have pnpm, run `corepack enable` first — it's bundled with Node.js.
</Callout>

## 1. Clone and Install

```bash
# Use as a GitHub template, then:
git clone https://github.com/YOUR_USERNAME/YOUR_REPO.git
cd YOUR_REPO
pnpm install
pnpm run dev
```

Open **<http://localhost:4321/>** — you should see the full demo site running locally.

<Callout type="success" title="First build?">
Design tokens compile automatically on the first `dev` or `build` command. No manual setup needed.
</Callout>

## 2. Personalize the Basics

Start with these three files to make the template yours:

### `src/config.ts`

Update the site title, author name, GitHub URL, and social links. Set any link to `""` to hide it from the UI.

### `src/content/bio/default.mdx`

Your name, title, location, skills, and social links. This file feeds the About page — change it once, and every surface updates.

### `src/content/experience/*.mdx`

Replace the demo entries with your actual work history. Each file is a separate job entry with title, company, dates, highlights, and technologies.

## 3. Customize the Design

The template uses semantic design tokens — no hardcoded colors anywhere.

```
tokens/base.json      → Brand colors (primary, secondary palettes)
tokens/semantic.json   → Semantic mappings (foreground, background, border)
tokens.css             → Generated CSS variables (auto-built)
```

Edit `tokens/base.json` to set your brand colors. Changes propagate automatically to all components, including dark mode.

<Callout type="warning" title="Don't hardcode colors">
Use semantic token classes like `text-foreground-primary` and `bg-background-secondary` — never `text-gray-600` or `bg-white`. This keeps dark mode and theming working correctly.
</Callout>

## 4. Add Your Content

### Blog Posts

Create a new directory under `src/content/blog/` with an MDX file inside:

```
src/content/blog/my-first-post/
├── my-first-post.mdx    # Your post content
├── hero.png              # Cover image (optional)
└── card.png              # Card thumbnail (optional)
```

The blog schema supports tags, technologies, cover images, related posts, and more — check `src/content.config.ts` for the full Zod schema.

### Projects

Same pattern under `src/content/projects/`. Each project is a case study with outcomes, technologies, and rich MDX content.

## 5. Deploy

The template is pre-configured for Cloudflare Pages, but works with any static host.

```bash
pnpm run build          # Production build → dist/
pnpm run preview        # Verify the build locally
```

One-click deploy buttons for Cloudflare, Netlify, and Vercel are in the README.

## 6. Run Quality Checks

Before shipping, verify everything passes:

```bash
pnpm run quality        # Format + lint + type-check
pnpm run test:unit      # Vitest unit tests
pnpm run test:e2e       # Playwright E2E tests
```

<Blockquote author="The Template Philosophy">
Ship zero JavaScript by default. Add interactivity only where it genuinely improves the user experience. Enforce this with budgets, not willpower.
</Blockquote>
